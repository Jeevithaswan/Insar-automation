# insar-automation

Automated Sentinel-1 SBAS InSAR pipeline (ISCE2 + MintPy) for any area of
interest, any date range, any track -- run one stage at a time from a plain
terminal, or via Docker. Same tools used for a manual ISCE2/MintPy analysis,
just called from code instead of by hand.

Stages: search/download Sentinel-1 SLCs (ASF) → DEM (Copernicus GLO-30) →
orbit files → ISCE2 stack setup/execution → MintPy time series → deliverables
(velocity map, time series plots, CSV, KMZ).

## Prerequisites

- An [Earthdata login](https://urs.earthdata.nasa.gov/) with `~/.netrc`
  configured -- required for Sentinel-1 SLC downloads via ASF.
- (Optional) a [CDS API key](https://cds.climate.copernicus.eu/) in
  `~/.cdsapirc` -- only needed if a config sets `mintpy.tropo_enabled: true`
  (ERA5 tropospheric correction).

## Setup

### Option A: conda environment

```bash
conda env create -f environment.yml
conda activate insar
```

### Option B: Docker

```bash
docker compose build
```

No local ISCE2/MintPy install needed -- everything runs inside the container.
`~/.netrc` and `~/.cdsapirc` are mounted read-only from your own home
directory at run time, never baked into the image.

## Running a new AOI

1. Copy the template -- don't edit it directly:
   ```bash
   cp configs/runs/template.yaml configs/runs/my_aoi.yaml
   ```
2. Fill in `run_id`, `aoi.bbox`, and `date_range` in `my_aoi.yaml`.
3. Find which Sentinel-1 track covers this AOI (writes a footprint map too):
   ```bash
   python pipeline.py tracks configs/runs/my_aoi.yaml
   ```
4. Run the stages in order, picking the track from step 3 via `--orbit`/`--direction`:
   ```bash
   python pipeline.py 0 configs/runs/my_aoi.yaml
   python pipeline.py 1 configs/runs/my_aoi.yaml --orbit <N> --direction <ASCENDING|DESCENDING>
   python pipeline.py 2 configs/runs/my_aoi.yaml
   python pipeline.py 3 configs/runs/my_aoi.yaml
   python pipeline.py 4 configs/runs/my_aoi.yaml
   python pipeline.py 5 configs/runs/my_aoi.yaml
   python pipeline.py 6 configs/runs/my_aoi.yaml
   python pipeline.py 7 <lat> <lon> configs/runs/my_aoi.yaml   # pick a reference point from stage 6's candidates
   python pipeline.py 8 configs/runs/my_aoi.yaml
   ```
   Every stage is checkpointed on disk (`runs/<run_id>/.done_markers/`) --
   interrupting and re-running a stage skips work already finished.

   Same commands under Docker: `docker compose run --rm insar <stage> configs/runs/my_aoi.yaml`.
   `run_all.sh [config_yaml]` runs stages 0-6 unattended via Docker, stopping
   once for the one genuine human decision the pipeline requires (the
   reference point for stage 7).

Full per-stage details and every config field are documented in
`pipeline.py`'s own module docstring and in the comments throughout
`configs/runs/template.yaml`.

## Repo layout

```
pipeline.py             single-file pipeline -- all stages
configs/runs/            per-AOI config files (template.yaml is the one to copy)
environment.yml          conda environment
Dockerfile / docker-compose.yml   containerized alternative to a local conda env
run_all.sh               unattended Docker run through stage 6
runs/                     run outputs (gitignored -- regenerated by re-running the pipeline)
```
